THE LESSON
  A Dictionary<K,V> enforces "each KEY has exactly one value" for free.
  It enforces NOTHING about values being unique - two keys may point at the
  same value quite legally.

  So whenever a problem describes a ONE-TO-ONE relationship (a BIJECTION),
  one dictionary gives you only half the constraint. You need the reverse
  map as well.

  Same shape appears in: Word Pattern, and any "can I consistently rename
  A to B" check.

REFINEMENTS (understood, not applied)
  - Both checks fit in a SINGLE loop - you are already at index i with both
    s[i] and t[i] in hand. Same O(n), one pass, less code.
  - Watch for declaring a variable and never using it (tMatch sat unused for
    a whole attempt). The compiler does not warn when it is initialized.
