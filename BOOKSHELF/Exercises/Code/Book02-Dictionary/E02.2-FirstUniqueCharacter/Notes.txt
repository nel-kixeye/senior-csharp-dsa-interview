THE TWO LESSONS

1. WHEN THE ANSWER IS A POSITION, ITERATE THE THING THAT HAS POSITIONS.
   Walking `s` by index means the answer IS i when the condition hits.
   Searching the dictionary throws the position away and then needs IndexOf
   to recover it - an extra O(n) scan AND wrong, because Dictionary
   enumeration order is UNDEFINED (not insertion order, not string order).

2. NESTED *ITERATION* IS THE PROBLEM, NOT NESTED INDEXING.
   dict[s[i]] is two indexers stacked and is O(1) - free.
   dict.FirstOrDefault(...) inside a loop walks the collection - O(n^2).
   C# lets you write iteration that LOOKS like a single operation.

   Before putting a call inside a loop, ask: DOES THIS SCAN?
     O(1), safe  : indexer, TryGetValue, HashSet.Add, HashSet.Contains
     O(n), fatal : List.Contains, IndexOf, Any, First, Count(pred), most LINQ

   Also learned: SEQUENTIAL loops ADD (n + n = O(n)). Only NESTED loops
   multiply. Two passes here is not a compromise - it is required, since you
   cannot know if s[0] is unique until the whole string has been counted.
