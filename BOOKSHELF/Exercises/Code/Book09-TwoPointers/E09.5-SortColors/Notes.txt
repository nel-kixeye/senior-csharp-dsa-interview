THE INVARIANT (why it is correct)
  [0 .. low)      all 0s        settled
  [low .. mid)    all 1s        settled
  [mid .. high]   UNEXAMINED    the working region
  (high .. end]   all 2s        settled

  value 0 -> swap with low. What comes back is a 1 (from the 1s region) or
            the same 0 (when low == mid). Either way ALREADY CLASSIFIED, so
            advancing mid is safe.
  value 1 -> already in the right region. Advance.
  value 2 -> swap with high. What comes back is from the UNEXAMINED region -
            unknown. Advancing mid would skip an unclassified element, so
            mid STAYS and re-examines.

  The question that unlocks it: WHAT DO I KNOW ABOUT THE VALUE THAT JUST
  ARRIVED AT MY SCANNER?

TWO POINTERS IS THREE DIFFERENT TECHNIQUES (Book 09 section 5)
  (a) CONVERGING   - lo/hi move toward each other.  E09.1, E09.2, E09.3, E09.4
  (b) READ/WRITE   - scanner + boundary, rearranging in place.  E03.1, E09.5
  (c) TWO SEQUENCES- walk two arrays together.  merge, subsequence

  E09.5 is (b) with THREE regions instead of two. The elimination argument
  from E09.2 does NOT apply here - that was about discarding candidates in
  sorted data. This is about maintaining a PARTITION INVARIANT. Different
  justification entirely.

NOTE
  The if/else-if/else partition (rather than if + continue) is the right
  structure here: three mutually exclusive values. else makes exhaustiveness
  structural instead of incidental - see the E01.2 equal-length bug.
